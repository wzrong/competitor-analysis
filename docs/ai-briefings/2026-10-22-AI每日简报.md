### ⭐ Claude Duet：把智能体做成一个会主动找你的 App

**核心观点**：这是 Claude 第一次把「主动性」当成产品形态而不是功能点。它不等于更强的聊天，而是改变了谁发起对话——过去是你打开 Claude，现在是 Claude 带着一份待办来找你。

产品定义很清楚：每天早上给你一份跨应用的简报，白天盯着接进来的应用，只在有事时才发消息。你可以把任务丢给它——排会议、整理未读邮件、追发票、做财务或销售预测、搭仪表盘、写网页应用——它在一个独立的虚拟机里跑，自带浏览器，你的手机和电脑关着它也继续干。

关键的约束都在「边界」上。发消息、付款、签文件、删内容之前，它会把动作摊开等你点确认；证券交易和账户间转账即便你批准也不做；支付走 Stripe 的 Link 和 Shopify 的 Shop Pay，用虚拟卡，真实卡号不外流。另有一个专门的分类器加系统提示，拦截信用卡号、政府证件号这类信息的流出请求。

成本模型同样值得注意。预览期它和 Claude 其他功能共享套餐额度，而它每隔几小时才检查一次账户——官方解释是全时轮询会更快烧完额度。这句话反过来说明：主动型智能体的真实门槛不是能力，是「监视」这件事本身的单价。

目前只对美国 Pro 和 Max 用户开放候补名单，独立 App，与主 Claude 应用暂时分开。官方也承认会误读对话、误判紧急程度，个人琐事类任务偏弱。

来源：[Claude](https://claude.com/blog/claude-duet) · [IT之家](https://www.ithome.com/1/016/169.htm)

### ⭐ 模型开进对手的云：OpenAI 与 Google Cloud 的合作意味着什么

**核心观点**：微软的独家期在 2026 年 4 月结束后，AWS 第二天就上了 Bedrock，如今 Google Cloud 成为第三家。模型公司正在把自己变成「谁都能卖的商品」，云厂商则把「谁都能托管」当成差异化。

具体安排是：GPT-6 Astra、Sol 与 Luna 三个前沿模型，加上 Codex 编程智能体，未来几周内上线 Model Garden 和 Google Cloud Marketplace。

这条新闻的看点不在技术，在渠道政治。Gemini Agent 是一个跨 Workspace、Microsoft 365 和 Slack 的通用工作智能体，它的设计逻辑是按任务动态路由到最合适的模型——此前只能在 Gemini 与 Claude 之间选，现在 OpenAI 也进了候选池。Google Cloud CEO Thomas Kurian 早前对路透的表态是，云平台应当对开发者欢迎的任何模型开放。

对开发者的实际影响是：同一份代码可以在三家云上换模型跑，锁定风险下降；对模型公司则是另一面——可替换性上升，价格和延迟会被直接比较。

### ⭐ PHP 的两个 9.2 分漏洞：AI 第一次在攻击者之前完成全球协调

**核心观点**：这不是一次普通的漏洞修复，而是一套流程的首次实战——AI 找到洞、厂商修复、多国机构在公开前完成部署准备。OpenAI 把它称作「防御者之窗」，同时承认同一能力也能被用来更快写利用。

漏洞被统称为 PHP2Shell，编号 CVE-2026-109618 与 CVE-2026-109619，CVSS v4.0 均为 9.2，可让未认证攻击者远程执行代码。PHP 支撑着业界估计约 70% 的网站。安全公司 Calif 借助 OpenAI 的 GPT-5.6 Sol 发现其中一项关键缺陷，谷歌旗下 Wiz 独立发现并报告了相关漏洞。

修复在公开前大约两个月就开始协调。PHP 官方维护者主导验证与开发，OpenAI、Wiz、Cloudflare 及多国网络安全机构参与跨机构协调，10 月 21 日发布 PHP 8.5.12、8.4.27、8.3.36、8.2.35。

配套动作比漏洞本身更重要：OpenAI 宣布投入 10 亿美元，通过 Daybreak for Frontline Defenders 向安全资源有限的关键服务组织提供补贴访问；并提出一套五阶段漏洞响应框架，从上游验证修复、提前通知受影响机构，到政府协作、跨产品更新准备与补丁发布后的部署支持。

一个不那么光彩的细节来自 Simon Willison：10 月 20 日 15:00 UTC 左右，两个 CVE 编号连同错误的发布时间和一个错误的 10.0 评分先在论坛和社交平台流传；PHP 项目因此把预告和发布整体提前了一天。Calif 还误发了一段 PoC 视频。

来源：[OpenAI](https://openai.com/index/coordinated-disclosure-of-critical-vulnerabilities) · [IT之家](https://www.ithome.com/1/016/173.htm) · [Simon Willison](https://simonwillison.net/2026/Oct/21/php-security-release/)

### ⭐ Flint：一个笔记本模型，和一条被公司承认的「AI 造 AI」流水线

**核心观点**：这条新闻的价值不在跑分，而在开发方式。Recursive 说自建的研究系统 Eureka Machine 参与了 Flint 从预训练、后训练到推理的几乎每个环节，让一个小团队四个月内从零做完一个模型。

规格很务实：MoE 架构，总参 40B、每个 token 只激活 2.5B，Apache 2.0 开源，权重在 Hugging Face 免费下载。在 M4 Pro 的 MacBook Pro 上约 131 token/秒，公司称约为同机 Gemma 4、Nemotron 3.5 Lightning 的 58 至 69 token/秒的两倍；在英伟达 RTX Spark 上超过 150。

Eureka 的具体贡献被列了三项：更稀疏的模型形状、把体积压小 71% 而质量几乎无损的低比特训练、以及加速底层计算的定制 kernel。SWE-Bench Verified 上，Flint 在同参数量级里领先；按公司自建的六项测试平均，只有阿里 Qwen3.8 27B 比它高。

限制也别忽略。公司承认它需要比付费编程助手更多的引导，建议把大任务拆小。作为对照，Meta 上周开源的 Muse Spark Open 是 816B 参数、至少需要 1TB 内存的另一个极端——端侧模型正在分成「能塞进笔记本」和「要两台 Mac Studio」两条路。

来源：[TechCrunch](https://techcrunch.com/2026/10/21/recursive-launches-flint-a-laptop-coding-model-it-says-was-largely-built-by-ai/) · [IT之家](https://www.ithome.com/1/016/148.htm)

### ⭐ 陶哲轩博客的客座文：数学是年轻人的学科，但这次是指「被挤压」

**核心观点**：这篇由数学家 Tristan Buckmaster 客座撰写的文章，是本周对 AI 公司最不客气的一份公开批评，而且它没有停留在能力之争，直接指向数据、署名和资源分配。

前半段仍是从容的。9 月 7 日陶哲轩与 Levent Alpöge 发布欧拉相关结果的当晚、也是 OpenAI 宣布纳维-斯托克斯结果的次日，他称之为「深蓝对卡斯帕罗夫时刻」。OpenAI 那份证明据称动用上万个智能体、历时 88 小时，成本以百万美元计，而悬赏是 100 万美元——这种算力对更广泛的数学界完全不可及。类比则是国际象棋：引擎出现后棋没有亡，高水平备战被民主化，产生了历史上分布最广的一代顶尖棋手。所以他说的「game is up」指的是学术竞赛的终结，不是学科的终结。

转折在后半段，而且很硬。文章指控 AI 公司「露天开采」数学家的数据，包括未发表的工作、私人笔记和基金申请书；称其既做模型又与自己付钱的客户竞争，存在明显利益冲突。具体事件是 10 月 6 日 OpenAI 发布数百份手稿，称平均只需单智能体三小时计算——文章说其中大量证明不可读、部分为假，而三小时的说法后来被承认没有计入多次失败尝试与其他智能体的前期工作。

作者的要求有三条：集体协议要普及到所有学者，并加入零数据保留与审计条款；学术评价不能只看谁先证出结果，要承认写作、工具、大型协作的贡献；AI 使用披露必须成为标准，而不是减分项。他还引了陶哲轩今年 ICM 的说法：数学正从「证明稀缺」走向「证明充裕」，而现有的署名体系是为稀缺时代建的。

来源：[陶哲轩博客](https://terrytao.wordpress.com/2026/10/21/mathematics-is-a-subject-for-the-young/)

## OpenAI

### 近 2000 个智能体一起读生物数据：32 分钟顶数月至一年

PerturbAI 与 OpenAI、斯克里普斯研究所联合发布了一套推理框架：约 2000 个智能体并行分析细胞反应、检索文献，再把实验结果与既有知识连成「推理图谱」。公司称分析其全脑基因组图谱只需 32 分钟，人工串行执行同类工作可能要数月至一年——这是公司估算，不是同期对照实验。

数据来自今年 3 月公布的全脑 CRISPR 图谱，覆盖约 800 万个细胞。在盲评中，生物学专家有 75% 的时候更偏好多智能体系统给出的解释，评估维度是新奇性、证据支撑、后续优先级和置信度。这反映的是报告偏好，不等于结论准确率。

来源：[IT之家](https://www.ithome.com/1/016/134.htm) · [OpenAI](https://openai.com/index/scaling-ai-research-for-complex-biological-data)

### 低资源语言：COBOL 迁移准确率从 5.4% 到 97.9%

OpenAI 发布了针对 COBOL、Fortran、Visual Basic 等低资源语言的评测与改进结果。这两个系列的语言公开代码少，却支撑着银行、ATM、天气预报和核安全分析等系统。

MultiLangBench 要求用 20 种语言从零构建兼容 SQLite 的数据库引擎。GPT-6 Astra 平均通过率 87.4%，上一代 GPT-5.6 Sol 是 26.8%；COBOL 从 10.9% 升到 72.1%，Visual Basic 从 27.5% 升到 89.4%。成本更低的 GPT-6 Luna 平均 40.3%，API 成本估算低约 78%。

在 COBOL 向 C++、Java、Python、Rust 迁移的评测里，GPT-6.1 Sol 低推理强度下准确率 86.6%，高强度下 97.9%，成本比上一代低 39%。公司反复强调，这类结果进生产环境仍需专家审查。

## 灵感种子

**「防御者之窗」是个会关闭的窗口**

PHP 这两个漏洞最有价值的信息不是 AI 找到了它，而是从发现到全球补丁部署之间的两个月协调期。这个窗口的宽度取决于三件事：厂商响应速度、云厂商能否提前拉起防护、以及各国机构的通报渠道。AI 让发现环节变快了，但修复和部署的节奏仍由人和流程决定。值得跟踪的是下一次同类事件里窗口会缩短还是拉长——如果缩短，说明防御方真的跑得比进攻方快；如果拉长，说明瓶颈从来不在发现。

**主动性是一种计费模式的产物**

Claude Duet 每隔几小时检查一次账户，官方给出的理由是会更快烧完额度。这句话透露了主动型智能体的经济学：它的核心开销不是回答，而是「持续在场」。这意味着产品设计会被定价反向塑形——便宜的档位就是更少的监视频率，更贵才有实时感。下一步值得看的是，是否会出现按「在线时长」而不是按 token 计费的助理套餐。

**过桥融资是把估值问题推给了下一个人**

OpenAI 以约 1.4 万亿估值融 300 亿，被描述为 IPO 的过桥。桥不产生经营现金流，产生的是时间；而时间的价格，就是下一轮谁来接。把这条逻辑和 CoreWeave 的 CDS 放在一起读会更清楚：股权端还在讲增长故事，债权端已经按 63% 的五年违约概率算账。两套价格之间的差，通常不是由其中一方修正，而是由一个具体事件抹平。

**模型开始给「老系统」记账**

COBOL 迁移准确率冲到 97.9%，看起来是个技术指标，实际是一张待办清单：全球银行、保险、航空的核心系统里有多少行 COBOL，就有多少个迁移项目在等着评估。这类工作过去因为「没人愿意做」而长期积压，价格由人工决定；现在第一次有了可对比的自动化报价。值得留意的是下一个被这样打开的低资源领域——很可能不是编程语言，而是各种专有格式的工程文档。
