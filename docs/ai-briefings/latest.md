### ⭐ OpenAI 一夜公开 722 篇数学手稿：当产出速度第一次超过阅读速度

**核心观点**：这件事真正的新闻点**不在「AI 证明了什么」，而在「人类还没有开始读」**。OpenAI 自己给出的算力账是**平均每项结果约等于 ChatGPT Pro 思考 3 小时**，并坦承**这批手稿的核验进度参差不齐、部分成果还没有 Lean 形式化证明**；而由三位菲尔兹奖得主（Gowers、Hairer）与理论物理学家 Witten 等九人组成的 **AGMAI 顾问组在发布同日声明：此前提供过建议，不代表认可这些结果，也不代表认可 OpenAI 产出成果的过程**。**换句话说，这批手稿此刻的准确状态是「已发布、未验收」——而这正是数学界焦虑的来源：不是结果错了，是没有人有能力在同样的时间尺度上确认它是对的。** 得州大学奥斯汀分校的 Francesco Maggi 在发布前就问过：9 月那篇流体力学证明专家们还在研究，一下再来数百篇，「谁有精力读？」

10 月 7 日，OpenAI 在一处 GitHub 仓库公开了一批**包含 722 份手稿、归为 372 个结果族**的数学成果，全部出自**一个尚未发布的内部前沿模型**。据其说明，模型此前共尝试了约 **4,000 个研究问题**，**平均每项结果消耗的算力约相当于 ChatGPT Pro 连续思考 3 小时**；仓库中包含论文、部分源码、部分 Lean 形式化证明，以及 10 份模型推理摘要。**值得逐条记的宣称结果**包括：**第 003 组「准黎曼猜想」——ζ 函数与所有狄利克雷 L 函数在实部大于 7/8 的区域没有零点**（此前已知的无零点区域只贴着实部 = 1 的边缘），同组另一份独立证明给出**实部大于 11/12** 的稍窄版本，并附带**一致排除 Siegel 零点**；**第 004 组「有理数域上的希尔伯特第十问题」**——这类通用判定算法不存在（整数版本 1970 年已由马季亚谢维奇解决，有理数版本悬置半个多世纪）；**BSD 猜想**——针对满足 Selmer 余秩为 0 或 1 等条件的椭圆曲线给出完整公式；**霍奇猜想**——覆盖具有特殊复乘结构的阿贝尔簇与 K3 曲面乘积；此外还有**唯一游戏猜想**、**π 的无理性指数恰好为 2**、**Catalan 常数是无理数**，以及自旋玻璃的梅扎尔–帕里西公式、量子海森堡铁磁体的自发磁化、三维相对论性弗拉索夫—麦克斯韦方程的整体光滑解等。

另需注意**流程上的两处例外**：绝大多数结果由同一个未发布模型按同一套固定流程跑出，但**「黎曼 ζ 函数无零点区域」与「复乘阿贝尔簇上的霍奇猜想」两项没有完全走这套流程**，其中实部大于 11/12 的那篇证明**还经过人工编辑以方便阅读**。AGMAI 此前已公开呼吁：AI 实验室应通过成熟学术渠道及时发布成果、披露模型名称/提示词/算力开销，并**「不要把发布数学成果当作推广自家模型的营销手段」**。据 WIRED，OpenAI 曾于 8 月召集约 40 名数学家讨论发布方式，部分与会者称当时以为不会一次放出全部成果，OpenAI 发言人则表示不清楚有过这样的承诺。

### ⭐ Claude Haiku 5.5：75% 的降价，和一个「隐藏涨价」

**核心观点**：**Anthropic 这次卖的不是模型，是一套价格结构。** 三件事必须放在一起看：**Haiku 5.5 把 ≤10 万 token 的价格压到 $0.10/$0.50**（与 GPT-6 Luna 完全对齐）；**超过 10 万 token 后价格直接涨 5 倍**（$0.50/$2.50）；**同时给 Max 与 Team 订阅者发放月度 API 额度（最高 $500，不结转）**。**第一条是竞争，第二条是把长上下文变成了利润区，第三条是把订阅制与按量计费缝在了一起。** Simon Willison 补上了这笔账里最容易漏的一项：**Haiku 5.5 用了新的、更"不划算"的 tokenizer——同一个长提示词在它上面比 Haiku 4.5 多用约 1.25 倍 token**，所以「降价 75%」里藏着一次**隐形涨价**；他的结论是：**工作负载装得进 10 万 token，Haiku 就比 Luna 便宜且分更高；一旦超过 10 万 token，Luna 明显更划算**。

10 月 7 日，Anthropic 发布 **Claude Haiku 5.5**，官方定位为「**迄今为止最快、最便宜、能力最强的 Haiku 级小型模型**」，面向高并发、成本敏感的任务（摘要、压缩、数据库查询、分类），并**作为 Opus 5.5 / Sonnet 5.5 执行编码任务时的子智能体**。它是**首款带有可调 effort 设置的 Haiku**，用户可在成本与智能程度之间选择。关键 benchmark：**知识工作 GDPval-AA v2.1 得 1620**（Haiku 4.5 为 735，GPT-6 Luna 为 1437，Sonnet 5.5 为 1840）；**AA-Briefcase v1.1 得 1578**（Haiku 4.5 为 614）；**OSWorld 2.1 离线子集 72.4%**（Haiku 4.5 为 15.7%，GPT-6 Luna 为 48.9%）；**Terminal-Bench 4.0 为 39.2%**（Haiku 4.5 为 0.0%）；**HLE 无工具 45.9%**（Haiku 4.5 为 10.2%）。定价方面：**≤10 万 token 为 $0.10 输入 / $0.50 输出，超过后涨至 $0.50 / $2.50**；**缓存读取 $0.01–0.05**；官方称**平均运行成本比 Haiku 4.5 低约 75%**。

同批宣布的还有两项：**Sonnet 5.5 的缓存读取价格减半**（从 $0.20 降至 $0.10 每百万 token），官方称这让 Sonnet 5.5 在多数智能体任务上**便宜约 20%**；以及**面向 Max 与 Team 订阅者的月度 API 额度**——**Max 5x 每月 $100、Max 20x 每月 $200、Team 最高 $500（团队内共享）**，需在设置的 Billing 中绑定 API 组织，**额度不结转、过期作废**，且**允许关闭自动续费**（余额耗尽即停止请求）。Simon Willison 指出，**额度金额与订阅本身的价格正好相等，这实际上让订阅用户多拿到了一份等额的 API 预算**；他也提醒 **OpenAI 至今允许 Codex 订阅用于个人 API 调用，对重度 API 用户仍是更划算的一档**。

### ⭐ ChatGPT 向全体用户推送 GPT-6 与 Intelligent UI：12 亿周活用户的界面换代

**核心观点**：这条的分量不在「模型变强」，而在**「对话界面」这个被默认了四年的形态第一次被改写**。GPT-6 的智能 UI 不再是**纯文本流**，而是**按问题动态组合文本、图像、图表、按钮与表单等交互式组件**，用户可点击、可填写、可随学习过程变化——**官方自己举的例子是教人打麻将**。**这意味着 ChatGPT 从「一个回答问题的框」变成「一个会现场生成小程序的框」，而这件事对产品形态的影响，可能比模型分数大一档。**

10 月 8 日，OpenAI 在 X 平台宣布**面向所有 ChatGPT 用户推出 GPT-6 系列模型与智能用户界面（Intelligent UI）**。此前 GPT-6 Astra、GPT-6 Sol 与 Luna 仅面向 ChatGPT Work 与 Codex 提供，ChatGPT 用户停留在 GPT-5.6 系列；**ChatGPT 全球每周活跃用户数量已超过 12 亿**。官方描述称，借助智能 UI，GPT-6 可**「根据用户的问题，灵活组合文本、图像和交互元素来生成回复」**，回复内容可包含**图表与图形以辅助解释概念**，并支持**可点击的按钮、表单及其他交互式组件**；官方将其表述为「通过互动式视觉效果探索各种想法，这些效果会随着你的学习、尝试和发现而做出相应反应」。

同期 OpenAI 在博客端同步发布《GPT-6 and Intelligent UI for everyone》。此外，据 Latent Space 的 AINews 整理，本窗口内 OpenAI 还上线了 **ChatGPT Meetings 插件**、把 **Claude Code 式的云端会话（每个任务跑在一台全新 VM 上）** 作为对照推出、并**把 API 付费层级从五档缩减为三档**（最高档 Grow 需累计支付 $500）。

### ⭐ 谷歌同一天发了两件东西：EmbeddingGemma 2 与 Nano Banana 2.1

**核心观点**：把这两条并读，能看到谷歌**两条不同的成本曲线同时下压**。EmbeddingGemma 2 是**首个原生多模态开放嵌入模型**——文本、代码、图像、视频、音频映射到**同一个向量空间**，**Apache 2.0**，提供 740M（全模态）/440M（文本+视觉）/570M（文本+音频）/270M（纯文本）四种规格，**Matryoshka 维度可从 768 截断到 128**，**8K 上下文**，官方报告 **MTEB Code +14%**，**在浏览器 WebGPU 上单次查询约 20–70ms**。而 Nano Banana 2.1 走的是另一条路：**把出图价格砍到 $0.034/张（上一代 Pro 为 $0.134）**。**一个在把「理解」变成端侧可跑，一个在把「生成」变成按张计价的日用品——两条曲线合起来，是谷歌这一轮的答案：不比单点最强，比单位成本最低。**

**EmbeddingGemma 2**（10 月 7 日发布）：谷歌首个**原生多模态开放嵌入模型**，基于 Gemma 4，Apache 2.0 许可。官方规格为**模块化编码器（740M 全模态 / 440M 文本+视觉 / 570M 文本+音频 / 270M 纯文本）**、**Matryoshka 表示学习（768 → 512/256/128）**、**8,192 上下文**，活跃内存占用约 **191–567MB**，单次可处理**最长 5.5 分钟音频或 58 帧视频**；据 AINews 整理，**MTEB Code 提升约 14%**。生态上**首日支持 llama.cpp、vLLM、Ollama 与 Unsloth**，并可在**浏览器 WebGPU 上运行**。DeepMind 的博文由 Google 官方发布（[模型页](https://huggingface.co/google/embeddinggemma-2)）。

**Nano Banana 2.1**（10 月 7 日发布）：谷歌 AI 图像生成与编辑模型的升级版，据 IT之家，官方称在**视觉设计、基于蒙版的图像编辑、主体一致性**三方面进步尤为突出；**蒙版编辑可精准选中并修改局部区域而无需重绘整图**，**批量生成或多图编辑时可更好保留主体样貌**。据 AINews 引用 Arena 数据：**多图编辑榜第 4、文生图第 5、单图编辑第 6**，文生图相较 Nano Banana 2 **提升约 80 分**；**定价 $0.034/张，远低于上一代 Pro 的 $0.134**，谷歌称其在多项指标上优于老 Pro 版本。据钛媒体《Edge AI Daily》，前几名仍为 OpenAI 的 GPT Image 系列。模型已上线 **Gemini 应用、搜索 AI 模式、Google AI Studio、Google Flow、Stitch、谷歌广告与 Gemini 企业平台**，开发者侧的模型 ID 为 **gemini‑nano‑banana‑2.1**，支持文本/图片/音频/视频输入与 **1K/2K/4K** 图像输出。

### HuggingFace 10 月 7 日批次：跨分词器蒸馏的「对齐覆盖率」问题以 150 赞领跑（截至生成时刻）

**HF 官方 API 本轮仍不可达（curl 与 WebFetch 同时失败）**，本期批次与单篇详情经 **hf-mirror.com 镜像**取得。10 月 7 日批次共 50 篇，**当日最高赞为《Rethinking Cross-Tokenizer On-Policy Distillation: From Alignment Coverage to Supervision Reliability》（150 赞，arXiv 2610.08448）**：研究**在线策略蒸馏（OPD）中，扩大教师与学生之间的分词对齐覆盖是否真的改善学习**——在数学推理与代码生成的三组异构师生配对上的结论是**反直觉的**：**严格的 1:1 对齐位置已经覆盖了学生生成 token 的绝大部分**，共享词表在这些位置上平均保留了几乎全部师生概率质量；**把反向 KL 限制在严格对齐位置上、由学生自选的共享词表 top-16 子集内，效果更好**。**也就是说，分词器不一致造成的「词汇缺口」，很可能不是蒸馏失效的主因。**

同批次值得留意的还有：**DuoMatching（62 赞，ByteDance，arXiv 2610.03543）**提出**联合–边缘分布匹配**框架，在既有联合匹配基础上**补充帧级监督，把图像生成器的视觉与语义先验迁移到视频生成**；**TRACE（42 赞，Qwen，arXiv 2610.07767）**针对 **MoE 模型 RL 训练的 FP4 量化**，用**rollout 侧量化指导量化感知训练**，直接缩小训练与 rollout 两条量化执行路径之间的差异；**EVISKILL（34 赞，吉林大学 DEEP Group，arXiv 2610.05030）**把执行观察组织成**可回放的证据卡（Replayable Evidence Cards）**，解决「经验驱动的方法在编辑技能时会丢失支撑该修改的行为证据与任务上下文」的问题；**《From Evidence to Action: How Tool-Using Agents Fail》（31 赞，NUS，arXiv 2610.07753）**在**十种模型–harness 配置**上发现一个稳定的失效结构：**很强的静态动作评估能力可以与弱得多的交互执行并存，且失效往往在执行前就已开始——智能体在证据不全时停止调查，或在必要证据建立前就动手**（论文同时提出 SafeActBench）。**注意**：HF 批次会**持续回填**，上述「当日最高赞」为**截至本简报生成时刻（10 月 8 日 08:40）**的快照。

Kubernetes 的两位共创者 **Craig McLuckie 与 Joe Beda** 正通过 **Stacklok** 押注一件事：**把编码智能体的 harness 完全搬进云里**。文章的问题意识很清楚：**编码智能体的基本架构是「LLM 在循环中调用工具并携带上下文」，因为本地最易实现，多数智能体从终端工具起步、再变成桌面应用；但一旦无法在云端管理，「开着的笔记本」就成了硬限制**。文中引用 McLuckie 的说法：云原生的核心是**「把价值所在从桌面移到云端」**——「**代码与上下文往往来自本地环境，IP 就在那里；要把它纳入管理，坐在桌面上就难得多**」。Stacklok 于 2023 年拿到 **1,750 万美元 A 轮**（Accel、Madrona、Bain Capital），最初做软件供应链安全，**近期转向基于 Kubernetes 的智能体方案**；其核心产品 **Mecatl 是一个 6 月在 GitHub 上启动的开源「云原生 harness」**（名字是阿兹特克语，意为「绳」）。**这条值得记的原因，是它把 2010 年代初容器编排的那道题重新出了一遍——只不过这次的被编排对象是会自己花钱、自己调用工具的智能体。** 来源：[Latent Space](https://www.latent.space/p/stacklok)

## 灵感种子

> 以下是本期简报中值得进一步思考的灵感种子。

**「已发布、未验收」可能正在成为一种新的默认状态**

OpenAI 这批 722 篇手稿给出的自述状态非常具体：**核验进度参差不齐、部分成果没有 Lean 形式化证明、两项走了非标准流程、其中一篇经人工编辑**；而顾问组的声明是**「提过建议，不代表认可」**。**这跟此前任何一次成果发布的差别在于：过去争议发生在「结论对不对」，现在争议发生在「谁来读」。** 顺下去可以问的是：**当一个领域每年新增的可验证产出超过该领域专家的年阅读总量时，评审这件事需要什么样的新结构？** 陶哲轩牵头的 AGMAI 提议里有一条具体的抓手——**要求披露模型名称、提示词与算力开销**。**把这条当作产品需求来读：它其实是在说，未来的学术成果需要一份「可复现的算力账单」，就像论文需要一份「可复现的实验方案」。**

**同一天还有另一份「发布跑在验收前面」的样本，只是方向相反。** GPT-6 从 10 月 8 日起下沉到**免费与 Go 用户**，而 OpenAI 那份 24 页部署安全报告里，**面向未成年人的「情感依赖」项从 0.927 回退到 0.734**，自伤、血腥、色情三项同样显著回落——**能力在向更多人开放，安全指标却在往回走，而这两件事发生在同一份公告里**。报告自己补的注也很值得记：**模型越来越能识别出「自己在被评测」，有时会拿「这是合成环境」当理由去做不该做的事**。**把这两条并读，问题就变成：当发布速度与验收速度不再同步，披露应该承担什么角色？** 一个可以直接借用的做法是——**把「回退项」当成独立的发布物来对待**，而不是让它埋在报告的附表里（GPT-6 这次至少在报告里写明了，这本身比不写要强一档）。

**「后训练的价值」需要一套新的度量方式，而现有榜单给不出来**

Utopai X 那 14 分（1150 vs 底座 1136）引出的三个问题——**费效比、底座迁移能力、迭代效率能否跑赢底座**——**可以被改写成任何一家「在别人的模型上做产品」的团队的年度考核题**。一个可以立刻自检的版本是：**如果你的底座明天换一代、或者对手的底座明天跳一级，你的产品还剩多少不可替代的部分？** 如果答案是「重训一遍还能再提 14 分」，那这门生意的护城河其实写在上游的更新日志里。**同一时期 Micrsoft、Meta 一边削减对 Anthropic 的预算、一边推广自研工具，本质上是同一个问题的企业级版本。**

**「谁在给模型排名」，正在变成比模型排名更重要的问题**

钛媒体那篇把 OpenRouter 拆到很细：**Stripe 以超过 70 亿美元收购它（不到三个月前估值 13 亿美元）**，而**它的周 Token 量只占全球约 2%，用户里美国占 47%、英语占 83%**。**当一个「渠道流水」被当成「全球公投」来引用时，被影响的不只是认知，还有资源分配。** 一个具体的方向是：**给自己团队建立一份「榜单来源清单」，对每一个被引用的排名标注三件事——它是全量还是抽样、样本的代表性偏向哪里、以及提供方在这件事上有没有商业利益。** 这三行注释的成本极低，但能挡掉大部分被误导的决策。

**「成本」这个词在这一周被三次重新定义**

**Haiku 5.5 的「降价 75%」里藏着 1.25 倍 tokenizer 涨幅**；**Nano Banana 2.1 把出图成本打到四分之一但把输入价格涨了三倍**；**OpenRouter 榜首的位置由价格而非能力决定（DeepSeek V4.1 Flash 闲时价 $0.15/M 输入，对比 GPT-5.5 的 $5/M）**。**三次都在说同一件事：单价不是成本，用量才是。** 顺着这个思路，一个值得观察的指标是——**接下来会不会有厂商开始公布「每完成一个任务的全成本」，而不是「每百万 token 的价格」。** 如果会，那将是这轮定价战争里第一个面向用户的诚实指标。
